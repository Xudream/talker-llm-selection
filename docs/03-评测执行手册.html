评测执行手册

> 配套：《02-Talker-LLM评测体系.md》（尺子1 公开集 / 尺子2 业务集）

> 目标：拿到仓库后 1 小时内能跑出第一个模型在尺子2 上的六轴成绩。

1. 环境


python3 --version          # 3.10+，只用标准库
export DASHSCOPE_API_KEY=sk-...   # 或 OPENAI_API_KEY；任意 OpenAI 兼容端点均可

2. 尺子2（业务集）三步跑通


cd ~/repos/projects/talker-llm-selection

# 1) 生成题集（场景 home / phone / both；档位 L0 120·场景 / L1 900 / L2 3000）
python3 tools/build_taskset.py --scene both --tier L0 --out tasksets/L0.jsonl
python3 tools/build_taskset.py --scene both --tier L1 --out tasksets/L1.jsonl

# 2) 跑模型
python3 tools/run_model.py --taskset tasksets/L1.jsonl --model qwen-plus \
  --base-url https://dashscope.aliyuncs.com/compatible-mode/v1 \
  --out predictions/qwen-plus__L1.jsonl

# 3) 判分（六轴 + 硬门槛 + 加权 + 三态）
python3 tools/score.py --taskset tasksets/L1.jsonl \
  --pred predictions/qwen-plus__L1.jsonl --report reports/qwen-plus__L1.md

自部署模型同一套命令，改 --base-url：


python3 tools/run_model.py --taskset tasksets/L1.jsonl --model qwen3.5-27b \
  --base-url http://127.0.0.1:8000/v1 --api-key dummy \
  --out predictions/qwen3.5-27b__L1.jsonl

3. 尺子1（公开集）

公开集不重造，用官方 harness 跑，再把结果填进统一表格：

集官方入口产出
BFCL v4github.com/ShishirPatil/gorilla（berkeley-function-call-leaderboard）单轮/多轮/并行/幻觉分 + Latency
τ²-benchgithub.com/sierra-research/tau2-bench三域闭环成功率
ACEBench官方仓库中文工具调用准确率
IFEval官方实现严格通过率
HaluEval-zh / CMMLU官方仓库幻觉倾向 / 中文常识

约定：

  1. 只抽样（见设计文档 §2.2），不跑全量，控制成本
  2. 统一 temperature=0、统一 prompt 模板；官方默认 prompt 与我们的差太多时，两版都跑并注明
  3. 尺子1 只做淘汰与摸高，最终定选看尺子2

4. 自检（不花 token）


python3 tools/run_model.py --taskset tasksets/L0.jsonl --backend dryrun --out predictions/oracle__L0.jsonl
python3 tools/score.py --taskset tasksets/L0.jsonl --pred predictions/oracle__L0.jsonl

仓库自带两个夹具（判分器测试用，不是模型成绩）：

文件期望结果
predictions/oracle__L0.jsonl100.0 分，全部硬门槛通过
predictions/mockbad__L0.jsonl淘汰（误调 75%、口语违规 100%、保真 ~32%）

5. 加一个候选

  1. 先判它在哪一轨：开源轨（进选型）还是闭源轨（摸高）
  2. 跑尺子1 → 过淘汰线 → 跑尺子2 L0 → L1 → 通过者进 L2
  3. 命名：<家族>-<尺寸>-<精度>__<档位>，如 qwen3.5-27b-fp8__L1

6. 怎么读报告

指标红线
工具闭环 ToolAccLoose< 60% 不用
误调率（A4）> 5%（家庭音箱 > 3%）淘汰
口语违规率> 2% 淘汰
事实保真< 98% 淘汰
空结果诚实< 95% 淘汰
TTFT P95> 800 ms 淘汰（云侧）
5 次一致率< 95% 查采样/缓存

7. 常见坑

现象原因处理
invalid 高模型不支持原生 tool calling改文本吐 JSON 的适配器，或换模型
A3 全 0只调第一次工具就收尾真实缺陷，不要放过
must_contain 全不中模型把数字换成中文读法本评测要求保留阿拉伯数字（便于 TTS 统一读法）
TTFT 恒为 None网关吞了 SSE检查是否强制非流式
分数虚高用 L1 调 prompt 后当最终成绩最终数字只来自 L2
