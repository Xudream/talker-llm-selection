1. 两把尺子的分工

尺子1（公开集）尺子2（业务集）
数据BFCL v4、τ²-bench、ACEBench、IFEval、中文常识/幻觉集自建：家庭音箱 + 手机助手真实说法

对象开源轨全部候选 + 闭源 SOTA（摸高）通过尺子1 的开源候选（2–4 个）

顺序：尺子1 先把"明显不行"和"明显够不着"的分开 → 尺子2 做业务定选 → 用摸高轨的分数解释"差距值多少钱"。

2. 尺子1：公开集

2.1 选集与用途

轴公开集覆盖用法已知局限
A 工具BFCL v4（单轮 AST / 多轮 / 并行 / 幻觉）函数选择、参数、该不该调主淘汰线英文 schema 为主
A 工具τ²-bench（retail / airline / telecom）多轮闭环、双控（用户/系统）两步闭环保守估计领域是客服，不贴家居
A 工具ACEBench（中文工具调用）中文说法 → 工具中文场景对照规模小
B 约束IFEval25 类可验证约束格式/长度底线不含"口语化"
C 事实HaluEval 中文子集 / SimpleQA 类幻觉倾向反向筛除与家居事实不同分布
C 常识CMMLU / C-Eval（抽样）中文常识闲聊兜底能力与工具无关
D 多轮BFCL multi-turn + τ²指代与槽位继承组合判断无"设备上下文"
E 时延BFCL 榜单 Latency 列Mean / P95只做初筛榜单环境≠我们的部署

> 门槛偏低是有意的：公开集分布不贴业务，够用来剔除"根本不行"的候选即可，真正的及格线在尺子2。

2.4 摸高轨怎么用

闭源 SOTA（Claude Opus 5 / GPT-6.x / Gemini / Doubao Pro / Qwen Max）跑同一套尺子1 + 尺子2 的 200 条抽样，得到"上限线"：


差距 = 上限线分数 − 最好的开源候选分数
性价比 = 差距 / 成本倍数

判断标准【自研归纳】：

  • 差距 ≤5pt：开源直接用，差距不值得付费
  • 差距 5–12pt：看尺子2 里差的是哪一类；若是"不该调"或"口语"这类可工程化修补的，仍选开源
  • 差距 >12pt：说明开源档根本不够，重新考虑模型规模或微调

3.6 判分

轴判分方式
A1/A2/A3函数名精确 + 参数 AST 比对（部分对记 0.5；两步需两跳都成功）
A4该静默却调用 = 误调；该确认却直接执行 = 误执行
B全规则：首句 ≤15 字、≤60 字、禁 markdown/列表/括号/emoji/"根据…"
Cmust_contain / must_not_contain 精确子串；空结果必须表达"没查到"
D最终工具调用与期望槽位比对
ETTFT P50/P95、首句时延
F同输入 5 次一致率

3.7 决策规则

硬门槛（任一不满足即淘汰）：JSON 合法率 ≥99%、误调率 ≤5%（家庭音箱 ≤3%）、口语违规 ≤2%、事实保真 ≥98%、空结果诚实 ≥95%、TTFT P95 ≤800 ms。

加权（满分 100）：工具闭环 35 / 口语 20 / 保真 15 / 多轮 10 / 时延 10 / 稳定 10。

三态：任一门槛不过 → 淘汰；全过且 ≥75 → 保留进 L2；其余 → 待定（最多迭代 3 轮）。

4. 两把尺子怎么串起来


① 尺子1（公开集，约 1,750 次/模型）
     开源候选 6–8 个 + 闭源 SOTA 3 个（摸高）
        ↓  淘汰线：BFCL 单轮 ≥75、多轮 ≥55、τ² ≥40、IFEval ≥80、该拒未拒 ≤15%
② 通过者 2–4 个 → 尺子2 L1（900 条/模型）
        ↓  硬门槛 + 加权 + 三态
③ 保留者 → 尺子2 L2（3,000 条）定稿
        ↓
④ 结论 = 定选模型 + 与摸高轨的差距（pt）× 成本倍数

时间：尺子1 约 1 天（含接入），尺子2 建集 5 人日 + 跑批 1 天。

6. 风险

风险影响回退
公开集与业务分布差距大尺子1 分数误导尺子1 只做淘汰；定选只看尺子2
真实转写不足尺子2 分布失真用合成顶，标 source=synthetic，并降低结论强度
闭源 API 版本漂移上限线不可复现记录模型 id + 日期，跨月不比较
自部署量化掉点选型结论失效一律以实际部署精度（FP8/AWQ）为准
工具 schema 变更历史结果不可比schema 版本号写进题集，跨版本不比较
