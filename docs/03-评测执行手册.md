# 评测执行手册

> 配套：《02-Talker-LLM选型评测集.md》（设计与口径）
> 目标：任何人拿到这个仓库，能在 1 小时内跑出第一个模型的六轴成绩。

---

## 1. 环境

```bash
python3 --version     # 3.10+
# 无第三方依赖：只用了标准库（urllib/json/re）
```

调用云 API 需要 key（任选其一）：

```bash
export DASHSCOPE_API_KEY=sk-...      # 阿里百炼兼容模式
export OPENAI_API_KEY=sk-...         # 任意 OpenAI 兼容端点
```

本地模型（vLLM / Ollama / llama.cpp server）都用同一套 OpenAI 兼容接口，改 `--base-url` 即可。

---

## 2. 三步跑通

```bash
cd ~/repos/projects/talker-llm-selection

# 1) 生成题集（L0 冒烟 120 条；L1 判定 900 条；L2 全量 3,000 条）
python3 tools/build_taskset.py --tier L0 --out tasksets/L0.jsonl

# 2) 跑模型（云 API 示例）
python3 tools/run_model.py --taskset tasksets/L0.jsonl \
  --model qwen-plus \
  --base-url https://dashscope.aliyuncs.com/compatible-mode/v1 \
  --out predictions/qwen-plus__L0.jsonl

# 3) 判分
python3 tools/score.py --taskset tasksets/L0.jsonl \
  --pred predictions/qwen-plus__L0.jsonl --report reports/qwen-plus__L0.md
```

本地模型示例（vLLM）：

```bash
python3 tools/run_model.py --taskset tasksets/L0.jsonl --model Qwen3.5-4B \
  --base-url http://127.0.0.1:8000/v1 --api-key dummy \
  --out predictions/qwen35-4b__L0.jsonl
```

## 3. 自检（不花 token）

```bash
# 用 gold 造 oracle，验证判分链路：应得 100 分、全门槛通过
python3 tools/run_model.py --taskset tasksets/L0.jsonl --backend dryrun --out predictions/oracle__L0.jsonl
python3 tools/score.py --taskset tasksets/L0.jsonl --pred predictions/oracle__L0.jsonl
```

仓库里已带两个自检产物，可直接对照：

| 文件 | 期望 |
|---|---|
| `predictions/oracle__L0.jsonl` | 100.0 分，全部门槛 ✅ |
| `predictions/mockbad__L0.jsonl` | 淘汰（误调 75%、口语违规 100%、保真 40%） |

这两个文件是**判分器的测试夹具**，不是模型成绩。

---

## 4. 加一个新候选

1. 按部署形态分组（端侧 / 边缘 / 云），不要跨档比较
2. 跑 L0 → 看 `invalid`/报错，确认协议通
3. 跑 L1 → 出六轴与三态结论
4. 通过后跑 L2 → 定稿

```bash
python3 tools/run_model.py --taskset tasksets/L1.jsonl --model <model> \
  --base-url <url> --out predictions/<model>__L1.jsonl
python3 tools/score.py --taskset tasksets/L1.jsonl \
  --pred predictions/<model>__L1.jsonl --report reports/<model>__L1.md
```

模型命名建议：`<家族>-<尺寸>-<量化>__<档位>`，例如 `qwen3.5-4b-awq4__L1`。

---

## 5. 怎么读报告

| 字段 | 含义 | 红线 |
|---|---|---|
| `工具闭环 ToolAccLoose` | 函数对 + 参数全对记 1，参数部分对记 0.5 | < 60% 直接不用 |
| `误调率（A4）` | 闲聊/缺参场景却调了工具 | **> 5% 淘汰** |
| `口语违规率` | markdown/列表/括号/超长/长首句 | **> 2% 淘汰** |
| `事实保真` | 数字与专名是否原样搬运 | **< 98% 淘汰** |
| `空结果诚实` | 工具空/超时是否说"没查到" | < 95% 淘汰 |
| `TTFT P95` | 首 token 时延 | 端侧 > 500 ms、云 > 800 ms 淘汰 |
| `5 次一致率` | 同输入重复 5 次的稳定性 | < 95% 要查采样/缓存 |

## 6. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `invalid` 高 | 模型不支持原生 tool calling，只会输出文本 | 换 `tool_choice` 策略或改用「文本里吐 JSON」再解析的适配器 |
| A3 全 0 | 模型只调第一次工具就收尾 | 这是真实能力缺陷，别改判分放过它 |
| `must_contain` 全不中 | 模型把数字换成中文（"十八到二十三度"） | 属正常现象，但要与"读法约定"对齐：本评测要求保留阿拉伯数字 |
| TTFT 总是 None | 走了非流式接口 | `run_model.py` 固定 `stream=True`，检查网关是否吞掉 SSE |
| 分数虚高 | 用 L0/L1 调过 prompt 后当最终成绩报 | 最终数字一律来自 L2；L1 只用于淘汰 |

## 7. 目录约定

```
tasksets/     题集（可重建，含 sha256）
predictions/  模型原始输出（含 TTFT）
reports/      判分报告（md）
tools/        build_taskset.py / run_model.py / score.py
docs/         洞察与设计
```

数据与预测都不含密钥；`predictions/` 里带模型原始输出，对外发布前先确认没有内部 prompt。
