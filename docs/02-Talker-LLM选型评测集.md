## 1. 评测要回答的三个问题

| # | 问题 | 对应轴 | 不过关的后果 |
|---|---|---|---|
| 1 | 说得**对**吗（工具选对、参数填对、闭环完成） | A | 用户要重复说、任务失败 |
| 2 | 说得**像人**吗（能直接念出来） | B | 听到"根据查询结果，为您找到以下 3 条…"立刻出戏 |
| 3 | 说得**快**吗（首字与整句时延） | E | 对话变对讲机 |

再加三条容易被忽略但会影响产品判断的：事实保真（C）、多轮指代（D）、稳定性（F）。

## 2. 六轴设计

### 2.1 A 轴：工具闭环（权重 35%）

| 子轴 | 考什么 | 判分 |
|---|---|---|
| A1 单步选择 | 给 8–20 个工具，选对函数 | 函数名精确匹配 |
| A2 参数填充 | 槽位、时间格式、枚举、单位 | AST 比对，数字与时间归一化后精确匹配 |
| A3 两步闭环 | 查→控（"看看明天天气，再决定要不要开加湿器"） | 两跳都成功才算过 |
| A4 不该调 / 该问 | 闲聊不该调；缺参数该澄清；写操作该二次确认 | 该静默却调用 = 误调（高危） |

公开集对标：BFCL v4 的 Single Turn（AST）+ Multi Turn【榜单】。自建集负责中文口语真实说法。

**A4 是主判据**：语音场景里"瞎调工具"的代价远高于"多问一句"。

### 2.2 B 轴：口语约束（20%）

全部可机器判定，不靠主观：

| 约束 | 判定方式 |
|---|---|
| 首句 ≤ 15 字 | 按标点切句，取第一句字数 |
| 总长 ≤ 60 字（或 ≤ 2 句） | 字符数 |
| 禁 markdown（`*` `#` `-` `|` `` ` ``） | 正则 |
| 禁有序/无序列表 | 正则 + 行首编号 |
| 禁括号补充（`（）` `()`） | 正则 |
| 禁 emoji | Unicode 区间 |
| 禁"根据/如下/以下"开头 | 前缀匹配 |
| 数字保留阿拉伯数字（便于 TTS 统一读法） | 中文数字比例 |

违规率 = 违规项数 / 样本数；单条 ≥3 项违规直接判该条失败。

### 2.3 C 轴：事实保真（15%）

| 子轴 | 例子 | 判分 |
|---|---|---|
| 数字/时间搬运 | 工具返回 "18:30，23℃" → 回复必须含 18:30、23 | 精确子串 |
| 专名搬运 | 歌名、地名、人名不得改写 | 精确子串 |
| 空结果不编 | 工具返回空 / 超时 / 无权限 | 必须表达"没查到"，出现具体数值即失败 |
| 单位正确 | 万元/元、公里/米 | 归一化后比对 |

这条对应洞察里那条硬事实：小模型参数知识幻觉率 80%+，所以**"不知道"是正确行为**。

### 2.4 D 轴：多轮与指代（10%）

| 子轴 | 例子 |
|---|---|
| 指代消解 | "那明天呢""换成刚才那首" |
| 槽位继承 | 上一轮说了城市，这一轮只说"那后天" |
| 纠错重述 | "不是北京，是上海" |
| 话题切换 | 从天气切到音乐，不得沿用旧槽位 |

判分：最终工具调用与期望槽位比对；无工具的场景用 judge 判指代是否指对。

### 2.5 E 轴：时延与吞吐（10%，硬门槛在外）

| 指标 | 口径 |
|---|---|
| TTFT（首 token） | 从提交到第一个流式 chunk，P50/P95 |
| 首句可播时延 | 到第一句完整（可送 TTS）的时长 |
| 整句时延 | 到 `finish` |
| 并发 1 / 4 / 8 | P95 与 OOM 边界 |

门槛（来自洞察 §4）：端侧 TTFT P50 ≤ 300 ms；边缘/云 P50 ≤ 500 ms、P95 ≤ 800 ms。

### 2.6 F 轴：稳定性（10%）

| 子轴 | 口径 |
|---|---|
| 同输入 5 次一致率 | temperature=0 应 100%；<95% 说明采样或缓存有问题 |
| 量化前后退化 | FP16 vs AWQ-4bit / Q4_K_M，工具成功率掉点 ≤3pt |
| 长上下文退化 | 8k 历史下工具成功率掉点 ≤5pt |
| JSON 合法率 | 结构化输出必须 ≥99% |

## 3. 样本量与统计

Wilson 区间，`半宽 = 1.96·√(p(1−p)/n)`。

| 档位 | 总量 | A | B | C | D | E | F | A 轴 CI |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| **L0 冒烟** | 120 | 48 | 24 | 16 | 16 | 8 | 8 | ±8.4pt（不判结论） |
| **L1 判定** | 900 | 360 | 180 | 120 | 120 | 60 | 60 | ±3.1pt |
| **L2 全量** | 3,000 | 1,200 | 600 | 400 | 400 | 200 | 200 | ±1.7pt |

三条设计依据：

1. **A 轴必须是最大盘**：它是淘汰赛唯一硬门槛（工具成功率），360 条才能把 90% 判到 ±3.1pt。
2. **A4 单独 ≥150 条**：误调率门槛是 5%，样本不足时 1 次误调就能让区间跨过门槛（参考 sidetalk 的教训：S0 少于 300 条时 FRR 结论不可用）。
3. **E 轴不进 CI**：时延是分布不是比例，报 P50/P95 + 样本数即可。

## 4. 数据来源与分层

| 来源 | 占比 | 说明 |
|---|---:|---|
| 真实语音转写（脱敏） | 50% | 含口音、重复、口误、断句 |
| 后台真实输出（结论句 + 字段） | 30% | 转述题的自然来源，天然带数字 |
| 人工构造边界题 | 20% | 空结果、超时、缺参、越权、近邻易混 |

意图族清单（每族最少条数）：

| # | 意图族 | L1 条数 | 备注 |
|---|---|---:|---|
| 1 | 闲聊/情感 | 80 | 不该调工具 |

| 3 | 音乐/播客控制 | 80 | 控制类 |
| 4 | 设备控制（灯/空调/闹钟） | 80 | 写操作，需确认 |
| 5 | 导航/出行 | 60 | 多槽位 |
| 6 | 通讯（电话/消息） | 60 | 写操作 + 权限 |
| 7 | 百科/汇率/单位换算 | 80 | 事实保真 |

## 6. 判分规则

### 6.1 四级判定

| 结果 | 条件 |
|---|---|
| 完全正确 | 工具调用与参数全对（或正确 abstain），文案满足全部约束，保真项全中 |
| 部分正确 | 函数对、参数部分对（≥1 个槽位错）→ 记 0.5 |
| 失败 | 函数错 / 缺调用 / 参数全错 |
| **误调** | A4 样本上调用任何工具（一票否决级） |

### 6.2 文案判分优先级

1. 结构约束（B 轴）先判——不合规直接失败，不再看内容
2. 保真（C 轴）——数字/专名精确匹配
3. 语义（D 轴、闲聊自然度）——judge 或人工，仅在前两步通过后

### 6.3 汇总指标

```
ToolAcc        = 完全正确 / N_A
ToolAccLoose   = (完全 + 0.5×部分) / N_A
twoHopRate     = A3 两跳都成功 / N_A3
overCallRate   = A4 误调 / N_A4          ← 硬门槛 ≤5%
clarifyRate    = A4 正确澄清 / N_A4
speechViolate  = 违规条数 / N_B           ← 硬门槛 ≤2%
factExact      = 保真项全中 / N_C          ← 硬门槛 ≥98%
emptyHonest    = 空结果说"没查到" / N_C2   ← 硬门槛 ≥95%
corefAcc       = 指代正确 / N_D
ttftP50/P95, firstSentenceP50/P95, consistency5x
```

## 7. 决策规则

### 7.1 硬门槛（任一不满足即淘汰）

| 门槛 | 阈值 | 为什么 |
|---|---|---|
| JSON 合法率 | ≥ 99% | 低于此，产品要写一堆容错 |
| 误调率（A4） | ≤ 5% | 语音场景瞎调工具比多问一句更伤 |
| 口语违规率 | ≤ 2% | 一条 markdown 就出戏 |
| 事实保真 | ≥ 98% | 数字错一次用户就不再信 |
| TTFT P95 | 端侧 ≤ 500 ms / 云 ≤ 800 ms | 见洞察 §4 |
| 内存/显存 | 端侧 ≤ 3 GB（Q4） | 与相机/导航抢内存 |

### 7.2 加权排序（通过硬门槛后，满分 100）

| 维度 | 权重 | 计分 |
|---|---:|---|
| 工具闭环 ToolAccLoose | 35 | 60%→0 分，90%→满分 |
| 口语约束 | 20 | 违规率 5%→0，0%→满分 |
| 事实保真 | 15 | 90%→0，100%→满分 |
| 多轮指代 | 10 | 70%→0，95%→满分 |
| 时延 | 10 | P95 800→0，300→满分 |
| 稳定性 | 10 | 一致率 90%→0，100%→满分 |

### 7.3 三态结论

| 情形 | 结论 | 下一步 |
|---|---|---|
| 任一硬门槛不满足 | 淘汰 | 不再投入 |
| 全部满足且加权 ≥75 | 保留 | 进 L2 全量复核 |
| 其余 | 待定 | 补测或调 prompt 后重跑（≤3 轮） |

## 8. 成本与排期

| 项 | 数量 | 估算 |
|---|---|---|
| L0 冒烟 | 12 候选 × 120 | 1,440 次调用，约 40 分钟 |
| L1 判定 | 10 候选 × 900 | 9,000 次调用；云 3 小时，本地 4B 约 8 GPU 时 |
| L2 全量 | 3 候选 × 3,000 | 9,000 次调用 |
| API 费用 | 约 20,000 次 × 500 token | < ¥100【估算】 |
| 建集 | 900 条 × 人工/半自动 | 5 人日 |

排期：D1 建 L0 + 跑通；D2–D3 建 L1 并跑 10 个候选；D4 统计与提名；D5 选中 3 个跑 L2。

## 10. 已知风险

| 风险 | 影响 | 回退 |
|---|---|---|
| 真实转写拿不到 450 条 | 分布失真 | 先用合成 + 后台日志顶，标注 `source=synthetic` |
| 公开集与自建集分布差异大 | 分数不可比 | 两套分开报，不混表 |
| judge 打分漂移 | B/D 轴不可复现 | B 轴全规则化；D 轴用槽位比对，judge 只做兜底 |
| 量化后能力掉太多 | 端侧结论失效 | 端侧结论一律以 Q4 实测为准，FP16 只作参考 |
| 工具 schema 变更多 | 历史结果失效 | schema 版本号写进 manifest，跨版本不比较 |
