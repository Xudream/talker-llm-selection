# Talker LLM 评测体系：尺子1（公开集）与尺子2（业务集）

> 配套：《01-业界方案洞察.md》（两轨候选池）、《03-评测执行手册.md》（怎么跑）
> 场景：家庭音箱 + 手机助手，云侧部署
> 版本：v2.0　｜　日期：2026-11-03

---

## 1. 两把尺子的分工

| | 尺子1（公开集） | 尺子2（业务集） |
|---|---|---|
| 数据 | BFCL v4、τ²-bench、ACEBench、IFEval、中文常识/幻觉集 | 自建：家庭音箱 + 手机助手真实说法 |
| 回答什么 | **谁不配进下一轮** + **上限在哪** | **谁最适合我们的业务** |
| 对象 | 开源轨全部候选 + 闭源 SOTA（摸高） | 通过尺子1 的开源候选（2–4 个） |
| 决策权 | 淘汰 + 摸高，不做定选 | 定选 |
| 成本 | 低（跑公开集） | 高（建集 + 人工） |

**顺序**：尺子1 先把"明显不行"和"明显够不着"的分开 → 尺子2 做业务定选 → 用摸高轨的分数解释"差距值多少钱"。

## 2. 尺子1：公开集

### 2.1 选集与用途

| 轴 | 公开集 | 覆盖 | 用法 | 已知局限 |
|---|---|---|---|---|
| A 工具 | **BFCL v4**（单轮 AST / 多轮 / 并行 / 幻觉） | 函数选择、参数、该不该调 | 主淘汰线 | 英文 schema 为主 |
| A 工具 | **τ²-bench**（retail / airline / telecom） | 多轮闭环、双控（用户/系统） | 两步闭环保守估计 | 领域是客服，不贴家居 |
| A 工具 | **ACEBench**（中文工具调用） | 中文说法 → 工具 | 中文场景对照 | 规模小 |
| B 约束 | **IFEval** | 25 类可验证约束 | 格式/长度底线 | 不含"口语化" |
| C 事实 | **HaluEval 中文子集 / SimpleQA 类** | 幻觉倾向 | 反向筛除 | 与家居事实不同分布 |
| C 常识 | **CMMLU / C-Eval**（抽样） | 中文常识 | 闲聊兜底能力 | 与工具无关 |
| D 多轮 | BFCL multi-turn + τ² | 指代与槽位继承 | 组合判断 | 无"设备上下文" |
| E 时延 | BFCL 榜单 Latency 列 | Mean / P95 | 只做初筛 | 榜单环境≠我们的部署 |
| F 稳定 | 自测重复 5 次 | 抖动 | 自测 | — |

### 2.2 抽样规模（控制成本）

| 集 | 全量 | 抽样 | 理由 |
|---|---:|---:|---|
| BFCL v4 单轮 | ~2,000 | 600 | ±3.8pt（p=0.8），够判 80/90 两档 |
| BFCL v4 多轮 | ~800 | 300 | ±4.5pt |
| τ²-bench | 3 域 | 每域 15 个任务 | 只判"能不能闭环"，不判细节 |
| ACEBench | ~1,000 | 300 | 中文对照 |
| IFEval | 541 | 全量 | 便宜 |
| HaluEval-zh | — | 200 | 只看倾向 |
| **合计** | — | **约 1,750 次调用/模型** | 云 API < ¥50/模型 |

### 2.3 尺子1 的判据

| 指标 | 门槛（淘汰线） |
|---|---|
| BFCL 单轮 AST | ≥ 75% |
| BFCL 多轮 | ≥ 55% |
| τ² 闭环成功率 | ≥ 40% |
| IFEval 严格通过率 | ≥ 80% |
| 幻觉"该拒未拒"率 | ≤ 15% |

> 门槛偏低是有意的：公开集分布不贴业务，够用来剔除"根本不行"的候选即可，真正的及格线在尺子2。

### 2.4 摸高轨怎么用

闭源 SOTA（Claude Opus 5 / GPT-6.x / Gemini / Doubao Pro / Qwen Max）跑同一套尺子1 + 尺子2 的 200 条抽样，得到"上限线"：

```
差距 = 上限线分数 − 最好的开源候选分数
性价比 = 差距 / 成本倍数
```

判断标准【自研归纳】：

- 差距 ≤5pt：开源直接用，差距不值得付费
- 差距 5–12pt：看尺子2 里差的是哪一类；若是"不该调"或"口语"这类可工程化修补的，仍选开源
- 差距 >12pt：说明开源档根本不够，重新考虑模型规模或微调

## 3. 尺子2：业务自建集

### 3.1 场景矩阵

| 能力族 | 家庭音箱 | 手机助手 |
|---|---|---|
| 闲聊/情感 | ✅ 高比例 | ✅ 中比例 |
| 设备控制 | ✅ 灯/空调/窗帘/扫地机 | ⚠️ 少（手机外设） |
| 内容播放 | ✅ 音乐/电台/有声书 | ✅ 音乐/播客 |
| 日程提醒 | ✅ 家庭日程、儿童作息 | ✅ 个人日程、会议 |
| 查询 | ✅ 天气/百科/菜谱 | ✅ 路线/营业时间/快递 |
| 通讯 | ⚠️ 家庭留言 | ✅ 微信/短信/通话 |
| 跨应用 | ❌ | ✅ 通知摘要、打车、导航 |
| 多轮指代 | ✅ | ✅ |
| 不该调/该问 | ✅ 写操作确认 | ✅ 隐私操作确认 |

### 3.2 六轴与配额

| 轴 | 权重 | 家庭音箱 L1 | 手机助手 L1 | 合计 |
|---|---:|---:|---:|---:|
| A1 单步选择 | — | 90 | 90 | 180 |
| A2 参数填充 | — | 60 | 60 | 120 |
| A3 两步闭环 | — | 25 | 25 | 50 |
| A4 不该调/该问 | — | 40 | 40 | 80 |
| B 口语约束 | 20% | 90 | 70 | 160 |
| C 事实保真 | 15% | 50 | 50 | 100 |
| D 多轮/上下文 | 10% | 50 | 60 | 110 |
| E 时延 | 10% | 30 | 30 | 60 |
| F 稳定 | 10% | 20 | 20 | 40 |
| **合计** | 100% | **455** | **445** | **900** |

工具闭环（A 轴）合计 430 条，权重 35%，是最大盘。三档样本量：

| 档 | 家庭 | 手机 | 合计 | A 轴 CI |
|---|---:|---:|---:|---:|
| L0 冒烟 | 60 | 60 | 120 | ±9pt（不判结论） |
| L1 判定 | 455 | 445 | 900 | ±3.1pt |
| L2 全量 | 1,500 | 1,500 | 3,000 | ±1.7pt |

### 3.3 两套工具集

| 家庭音箱 | 手机助手 |
|---|---|
| `control_light(room,on,level)` | `send_message(app,contact,content)` |
| `set_ac(mode,temperature)` | `read_notifications(limit)` |
| `control_curtain(room,action)` | `create_calendar(title,time)` |
| `control_vacuum(mode,room)` | `navigate_to(destination,mode)` |
| `play_music(song/playlist)` | `play_music(song/playlist)` |
| `create_reminder(content,time,who)` | `call_contact(name)` |
| `get_weather(city,date)` | `get_weather(city,date)` |
| `get_recipe(dish)` | `get_route_eta(destination)` |
| `family_announce(content)` | `summarize_notifications(app)` |

**schema 不混用**：用同一套工具集测两个场景，测到的是"模型对陌生 schema 的泛化"，不是业务能力。

### 3.4 数据来源

| 来源 | 占比 | 说明 |
|---|---:|---|
| 真实语音转写（脱敏） | 50% | 含口音、口误、断句；家庭场景还有多人交叉 |
| 后台真实输出（结论 + 字段） | 30% | 转述题与保真题的来源 |
| 人工构造边界题 | 20% | 空结果、超时、缺参、越权、近邻易混 |

### 3.5 记录 schema

```json
{
  "id": "talker-home-A2-light-0007",
  "scene": "home",
  "axis": "A2",
  "family": "light",
  "turns": [{"role": "user", "text": "把客厅灯调暗一点"}],
  "tools": ["control_light", "set_ac", "control_curtain"],
  "gold": {"tool_call": {"name": "control_light",
                          "args": {"room": "客厅", "on": true, "level": 30}}},
  "constraints": {"first_sentence_max_chars": 15, "max_chars": 60, "no_markdown": true},
  "meta": {"source": "real_transcript", "far_field": true, "tv_on": true}
}
```

### 3.6 判分

| 轴 | 判分方式 |
|---|---|
| A1/A2/A3 | 函数名精确 + 参数 AST 比对（部分对记 0.5；两步需两跳都成功） |
| A4 | 该静默却调用 = 误调；该确认却直接执行 = 误执行 |
| B | 全规则：首句 ≤15 字、≤60 字、禁 markdown/列表/括号/emoji/"根据…" |
| C | must_contain / must_not_contain 精确子串；空结果必须表达"没查到" |
| D | 最终工具调用与期望槽位比对 |
| E | TTFT P50/P95、首句时延 |
| F | 同输入 5 次一致率 |

### 3.7 决策规则

硬门槛（任一不满足即淘汰）：JSON 合法率 ≥99%、误调率 ≤5%（家庭音箱 ≤3%）、口语违规 ≤2%、事实保真 ≥98%、空结果诚实 ≥95%、TTFT P95 ≤800 ms。

加权（满分 100）：工具闭环 35 / 口语 20 / 保真 15 / 多轮 10 / 时延 10 / 稳定 10。

三态：任一门槛不过 → 淘汰；全过且 ≥75 → 保留进 L2；其余 → 待定（最多迭代 3 轮）。

## 4. 两把尺子怎么串起来

```
① 尺子1（公开集，约 1,750 次/模型）
     开源候选 6–8 个 + 闭源 SOTA 3 个（摸高）
        ↓  淘汰线：BFCL 单轮 ≥75、多轮 ≥55、τ² ≥40、IFEval ≥80、该拒未拒 ≤15%
② 通过者 2–4 个 → 尺子2 L1（900 条/模型）
        ↓  硬门槛 + 加权 + 三态
③ 保留者 → 尺子2 L2（3,000 条）定稿
        ↓
④ 结论 = 定选模型 + 与摸高轨的差距（pt）× 成本倍数
```

时间：尺子1 约 1 天（含接入），尺子2 建集 5 人日 + 跑批 1 天。

## 5. 成本与统计

| 项 | 数量 | 估算 |
|---|---|---|
| 尺子1 | 11 模型 × 1,750 | 19,250 次调用，云 API < ¥60/模型【估算】 |
| 尺子2 L1 | 4 模型 × 900 | 3,600 次调用 |
| 尺子2 L2 | 2 模型 × 3,000 | 6,000 次调用 |
| 自部署推理 | 9B/27B 单机 | 约 20 GPU 时 |
| 建集 | 900 条 | 5 人日 |

统计纪律：Wilson 95% CI；差异小于 CI 宽度写"不可区分"；dev/test 隔离（尺子2 的 L1 可调 prompt，L2 只报一次）。

## 6. 风险

| 风险 | 影响 | 回退 |
|---|---|---|
| 公开集与业务分布差距大 | 尺子1 分数误导 | 尺子1 只做淘汰；定选只看尺子2 |
| 真实转写不足 | 尺子2 分布失真 | 用合成顶，标 `source=synthetic`，并降低结论强度 |
| 闭源 API 版本漂移 | 上限线不可复现 | 记录模型 id + 日期，跨月不比较 |
| 自部署量化掉点 | 选型结论失效 | 一律以实际部署精度（FP8/AWQ）为准 |
| 工具 schema 变更 | 历史结果不可比 | schema 版本号写进题集，跨版本不比较 |
